# Dataset-Aware Conformal Calibration for Cross-Dataset Lithium-Ion Battery State-of-Health Prediction

Code, trained models, and a machine-generated results registry for the paper of the same title
(submitted to the *Journal of Energy Storage*).

The pipeline forecasts lithium-ion battery state of health (SOH) from capacity-fade curves pooled
across **seven public datasets** (NASA, CALCE, Oxford, MIT/Severson, BIT, XJTU, RWTH Aachen; 339
cells, 337 contributing at least one windowed sample). A multi-scale bidirectional LSTM with
self-attention produces point forecasts and MC-Dropout uncertainty; several conformal calibration
strategies turn those into prediction intervals with a distribution-free coverage guarantee:
pooled, groupwise (Mondrian), normalized-groupwise, an empirical-Bayes hierarchical (partial-
pooling) calibration, and a maximum-mean-discrepancy-weighted heterogeneity-guided conformal
predictor (HGC-CP).

## What makes this repository's numbers trustworthy

Every number reported in the paper is generated by `make_results_registry.py` from saved model
outputs — never hand-typed. `results_registry.json` and `paper/numbers.tex` are the single source
of truth; `paper/main.tex` references them exclusively. `ERROR_REGISTER.md` and `TEST_REPORT.md`
document every defect found and fixed during an independent verification pass over this pipeline,
with evidence, severity, and status for each — including cases where a result initially looked
wrong, was investigated, and the investigation itself is recorded (not just the fix). This is
intentional: a reproducible, audited pipeline is a stronger basis for a published claim than one
where the development history is hidden.

## Method at a glance

| Stage | What happens | File |
|---|---|---|
| Loading | One parser per dataset turns raw files into `(dataset, cell_id, cycle, capacity)` rows | `*_loader.py` |
| SOH | `SOH = capacity / median(capacity of first 3 cycles)`, per cell | `preprocessing.py` |
| Split | Cell-independent, stratified by dataset (70/15/15); `config.SPLIT_SEED` kept separate from the model-init seed so split- and seed-variability can be studied independently | `preprocessing.py` |
| Windows | 20 past cycles -> SOH one cycle ahead | `preprocessing.py`, `config.py` |
| Model | Two BiLSTM branches (full resolution + pooled) -> concatenation -> self-attention -> MLP head | `model.py` |
| Uncertainty | MC-Dropout, 30 stochastic forward passes (explicit scope: post-fusion/head dropout only, not the LSTM's internal recurrent dropout — see `model.py`) | `model.py`, `train.py` |
| Calibration | Split conformal (pooled / groupwise / normalized-groupwise), predictor-consistent (calibration and test nonconformity scores from the same predictor) | `conformal.py`, `train.py` |
| Hierarchical calibration | DerSimonian-Laird empirical-Bayes partial pooling across datasets | `hierarchical_calibration_v2.py` |
| HGC-CP | MMD-weighted conformal quantile + heterogeneity inflation, nested held-out hyperparameter search | `hgc_cp.py`, `nested_hyperparameter_search.py`, `run_nested_hp_search_all.py` |
| Model-level generalization | Leave-one-dataset-out (entire dataset withheld from training) | `leave_one_out.py` |
| Repeated splits | Independent cell-level split seeds, model-init seed held fixed | `repeated_split_experiment.py` |

## Installation

Python 3.10 was used.

```bash
pip install -r requirements_frozen.txt
```

A CUDA GPU is used automatically if available; everything also runs on CPU (training steps will
be slow).

## Reproducing the results

See `REPRODUCIBILITY.md` for the exact environment, raw-data folder layout, and full run order.
`run_all.py` is a reference driver that prints a dry-run plan by default and only executes a step
when its primary output is missing (pass `--execute`); use `--only <step names>` to run one stage
at a time rather than the whole pipeline back to back.

```bash
python run_all.py                 # print the plan, run nothing
python run_all.py --execute --only preprocessing train
```

## Reference results and the audit trail

`ERROR_REGISTER.md` documents every defect found during an independent re-verification of this
pipeline — including the ones that changed reported numbers (e.g. a predictor-consistency bug in
the leave-one-dataset-out evaluation, a stale hard-coded significance-test input, data-quality
artifacts in two of the seven raw datasets) and the ones that didn't (documentation gaps,
performance-only refactors). `TEST_REPORT.md` is a stage-by-stage PASS/FAIL log. `tests/` contains
runnable unit and property tests that don't require a GPU or the raw datasets.
